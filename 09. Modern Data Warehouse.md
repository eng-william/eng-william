## 🧠 1. A filosofia do MDW

O **Modern Data Warehouse (MDW)** surgiu por volta de **2011** como a ideia de “**o melhor de dois mundos**”.

No início do Big Data, houve uma tentativa de substituir totalmente o **Data Warehouse relacional** por **Data Lakes**, mas isso falhou porque os Data Lakes eram **difíceis de consultar** para usuários de negócio.

O MDW resolve isso unindo **Data Lake + DW relacional**, cada um fazendo o que sabe fazer melhor.

---

<a id="como-funciona"></a>
## ⚙️ 2. Como a arquitetura funciona

Na prática, o MDW funciona assim:

* **Data Lake** → recebe e prepara dados em grande volume.
* **Data Warehouse Relacional** → entrega dados finais com qualidade, segurança e performance.

Isso permite que:
* Cientistas de dados explorem e testem hipóteses no Lake.
* Usuários de negócio consumam dados prontos e rápidos no DW.

### 🔁 Mini diagrama de fluxo

```
Fontes → Ingestão → Data Lake → Transformação
                         ↓
                   Modelagem (DW)
                         ↓
               BI / Dashboards / ML
```

<a id="cinco-etapas"></a>
## 🧭 3. As 5 etapas de construção

Um MDW segue um fluxo lógico com cinco estágios:

### 1) 📥 Ingestão (Ingest)
Dados chegam de várias fontes: CRM, ERP, IoT, redes sociais, APIs.

### 2) 🗄️ Armazenamento (Store)
Os dados são guardados no **Data Lake**, de forma econômica e rápida.

### 3) 🧹 Transformação (Transform)
Os dados são limpos e preparados **dentro do Lake**, o que costuma ser mais barato.

### 4) 🧱 Modelagem (Model)
Os dados de alto valor vão para o **DW relacional** em modelos estruturados (Star Schema ou 3NF).

### 5) 📊 Visualização e ML (Visualize/ML)
* Dashboards e relatórios para o negócio.
* Dados preparados para Machine Learning e experimentação.

<a id="por-que-moderna"></a>
## 🚀 4. Por que essa arquitetura é “moderna”

O termo **moderno** se refere à capacidade de lidar com:
* **Volume**
* **Velocidade**
* **Variedade**

E faz isso usando **tecnologias de nuvem**, que escalam conforme a necessidade.

Além disso, o MDW combina duas abordagens:

* **Bottom-up (Data Lake):** explorar primeiro, descobrir perguntas depois.
* **Top-down (Data Warehouse):** organizar dados para perguntas já conhecidas e críticas.

---

<a id="evolucao"></a>
## 🔄 5. Evolução e continuidade

O MDW não é o fim da linha. Ele pode evoluir para:

* **Data Fabric:** adiciona camadas de automação e metadados.
* **Data Lakehouse:** tenta simplificar a arquitetura eliminando o DW relacional.

Essas evoluções trazem benefícios, mas também novos desafios.
