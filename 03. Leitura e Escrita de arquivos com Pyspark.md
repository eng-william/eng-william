## 1. Introdução

No Databricks, a manipulação de arquivos de dados (leitura e escrita) é feita principalmente com a API do **Spark** em PySpark: `spark.read` para ler e `df.write` para gravar. Os formatos mais usados no dia a dia de um engenheiro de dados são **CSV**, **JSON** e **Parquet**.

Este material cobre:

- **CSV:** leitura com e sem opções (separador, cabeçalho, inferência de tipos), gravação e compactação em GZIP.
- **JSON:** leitura, gravação e compactação em GZIP.
- **Parquet:** leitura, gravação, comparação com CSV/JSON, e **particionamento** (por uma ou mais colunas) para ganho de performance em leituras filtradas.

Os exemplos usam caminhos no **DBFS** (ex.: `/FileStore/tables/...` ou `dbfs:/FileStore/tables/...`). A mesma lógica vale para dados em Volumes ou em storage montado (ex.: Azure Data Lake).

---

## 2. Estrutura comum: ler e gravar com Spark

Antes de entrar em cada formato, vale lembrar o padrão:

- **Ler:** `spark.read.format("csv")` (ou `.csv()`, `.json()`, `.parquet()`) + `.option(...)` + `.load(caminho)`.
- **Gravar:** `df.write.format("csv")` (ou `.csv()`, etc.) + `.option(...)` + `.mode("overwrite" | "append" | "ignore")` + `.save(caminho)`.

O Spark costuma gerar **pastas** com vários arquivos (partes), principalmente em escritas distribuídas. O `caminho` é o diretório onde os arquivos serão criados, não um único arquivo.

---

## 3. Arquivos CSV

CSV é um formato de texto simples, muito usado para troca de dados e fontes como planilhas e exportações. No Spark você controla separador, presença de cabeçalho e inferência de tipos.

### 3.1. Leitura básica

Forma mais simples: apenas o caminho. As colunas podem vir como `_c0`, `_c1`, etc., e os tipos podem ser todos string.

```python
caminho_csv = "dbfs:/FileStore/tables/dados/entrada.csv"
df = spark.read.csv(caminho_csv)
display(df)
```

Para já informar cabeçalho e inferência de esquema (recomendado quando o arquivo tem header):

```python
df = spark.read.csv(caminho_csv, header=True, inferSchema=True)
display(df)
```

### 3.2. Leitura com opções (separador, cabeçalho, esquema)

Quando o CSV usa **separador diferente** (ex.: `;`), tem **linhas iniciais para pular** ou você quer controle fino, use `.format("csv")` e `.option()`:

```python
df = spark.read \
    .format("csv") \
    .option("header", True) \
    .option("sep", ";") \
    .option("inferSchema", True) \
    .option("skipRows", 1) \
    .load("/FileStore/tables/dados/entrada.csv")

display(df)
```

| Opção | Descrição | Exemplo |
|-------|-----------|---------|
| `header` | Primeira linha é cabeçalho | `True` ou `"true"` |
| `sep` | Separador de colunas | `","`, `";"`, `"\t"` |
| `inferSchema` | Inferir tipos (int, double, date, etc.) | `True` |
| `skipRows` | Quantas linhas pular no início | `1`, `2` |

Se o arquivo foi salvo pelo Spark **sem** cabeçalho, as colunas podem vir como `_c0`, `_c1`. Nesse caso você pode renomear depois:

```python
df = df.withColumnRenamed("_c0", "ID") \
       .withColumnRenamed("_c1", "Nome") \
       .withColumnRenamed("_c2", "Telefone") \
       .withColumnRenamed("_c3", "Email")
```

### 3.3. Gravar CSV

A gravação gera uma **pasta** com arquivos part-*.csv. Use `option("header", "true")` se quiser cabeçalho na saída.

```python
df.write \
    .format("csv") \
    .option("header", "true") \
    .option("sep", ";") \
    .mode("overwrite") \
    .save("/FileStore/tables/dados/saida_csv")
```

- **overwrite:** substitui o conteúdo existente na pasta.
- **append:** adiciona à pasta (cuidado com cabeçalho duplicado).
- **ignore:** só grava se a pasta não existir.

### 3.4. CSV compactado (GZIP)

Compactar reduz o tamanho do arquivo e o custo de armazenamento em nuvem. Para **gravar** CSV em GZIP:

```python
df.write \
    .format("csv") \
    .option("compression", "gzip") \
    .option("header", "true") \
    .option("sep", ";") \
    .mode("overwrite") \
    .save("/FileStore/tables/dados/entrada_csv_compactado")
```

Para **ler** o CSV compactado, informe a opção de compactação:

```python
df_novo = spark.read \
    .option("compression", "gzip") \
    .option("header", "true") \
    .option("inferSchema", "true") \
    .option("sep", ";") \
    .csv("/FileStore/tables/dados/entrada_csv_compactado")

display(df_novo)
```

## 4. Arquivos JSON

JSON é comum em APIs e dados semi-estruturados. O Spark lê cada linha do arquivo (ou cada objeto em alguns modos) e infere o esquema.

### 4.1. Leitura

Leitura direta pelo método `.json()`:

```python
df = spark.read.json("dbfs:/FileStore/tables/dados/entrada.json")
display(df)
```

O Spark infere os tipos com base no conteúdo. Se precisar renomear colunas:

```python
df = df.withColumnRenamed("coluna_destino", "destino") \
       .withColumnRenamed("coluna_origem", "origem") \
       .withColumnRenamed("tipo_ocorrencia", "categoria")
display(df)
```

### 4.2. Gravação e compactação

Gravar em JSON (pasta com arquivos):

```python
df.write \
    .format("json") \
    .mode("overwrite") \
    .save("/FileStore/tables/dados/saida_json")
```

Gravar **compactado em GZIP** (reduz bastante o tamanho; por exemplo, um JSON de 20 MB pode cair para cerca de 3 MB):

```python
df.write \
    .format("json") \
    .option("compression", "gzip") \
    .mode("overwrite") \
    .save("/FileStore/tables/dados/dados_json_compactado")
```

### 4.3. Ler JSON compactado

Ao ler, informe a compactação:

```python
df_compactado = spark.read \
    .option("compression", "gzip") \
    .json("/FileStore/tables/dados/dados_json_compactado")

display(df_compactado)
```

## 5. Arquivos Parquet

Parquet é um formato **colunar**, compactado e muito usado em Data Lakes e pipelines. No Databricks e no Spark ele é a escolha habitual para dados que serão consultados ou processados várias vezes.

### 5.1. Por que usar Parquet

Em comparação com CSV e JSON (no mesmo conjunto de dados), em geral observa-se:

- **Menor armazenamento** (na ordem de dezenas de porcento a menos que CSV/JSON), o que reduz custo em nuvem.
- **Leitura mais rápida** (o motor lê só as colunas necessárias e aproveita estatísticas).
- **Particionamento** nativo: você pode particionar por colunas (ex.: data, estado) e ler apenas as partições que interessam.

Por padrão o Parquet no Spark usa compactação **Snappy**. Você pode trocar para **GZIP** se priorizar ainda mais tamanho em disco.

### 5.2. Gravar Parquet

Forma simples:

```python
df.write \
    .format("parquet") \
    .mode("overwrite") \
    .save("/FileStore/tables/dados/vendas.parquet")
```

Equivalente usando atalho:

```python
df.write.mode("overwrite").parquet("/FileStore/tables/dados/vendas.parquet")
```

A saída é uma **pasta** com arquivos `.parquet` (e metadados). Para inspecionar:

```python
display(dbutils.fs.ls("/FileStore/tables/dados/vendas.parquet/"))
```

### 5.3. Ler Parquet

Leitura direta (pasta inteira):

```python
df_parquet = spark.read.parquet("/FileStore/tables/dados/vendas.parquet")
display(df_parquet)
```

Ou usando `.format()` e `.load()`:

```python
df_parquet = spark.read \
    .format("parquet") \
    .load("dbfs:/FileStore/tables/dados/vendas.parquet")
display(df_parquet)
```

### 5.4. Parquet com compactação GZIP

Para reduzir ainda mais o tamanho (em troca de um pouco mais de CPU na escrita/leitura):

```python
# Gravar com GZIP
df.write \
    .format("parquet") \
    .option("compression", "gzip") \
    .mode("overwrite") \
    .save("/FileStore/tables/dados/vendas_compactado.parquet")

# Ler (o Spark detecta a compactação automaticamente na maioria dos casos;
# se necessário, use .option("compression", "gzip"))
df_gzip = spark.read \
    .option("compression", "gzip") \
    .parquet("/FileStore/tables/dados/vendas_compactado.parquet")
display(df_gzip)
```

## 6. Particionamento Parquet

Particionar significa gravar os dados em **subpastas** por valor de uma ou mais colunas (ex.: `estado=SP`, `categoria=Ativo`). Assim, ao filtrar por essas colunas, o Spark lê só as pastas necessárias, o que melhora performance e reduz custo de leitura.

### 6.1. Particionar por uma coluna

Antes de gravar, use `.partitionBy("nome_da_coluna")`:

```python
df_parquet = spark.read.parquet("/FileStore/tables/dados/vendas.parquet")

df_parquet.write \
    .partitionBy("categoria") \
    .mode("overwrite") \
    .parquet("/FileStore/tables/dados/vendas_por_categoria")
```

A estrutura fica, por exemplo:

- `vendas_por_categoria/categoria=Ativo/`
- `vendas_por_categoria/categoria=Inativo/`
- ...

Para listar as partições:

```python
display(dbutils.fs.ls("dbfs:/FileStore/tables/dados/vendas_por_categoria/"))
```

### 6.2. Particionamento múltiplo

Você pode particionar por mais de uma coluna. A ordem define a hierarquia das pastas:

```python
df_parquet.write \
    .partitionBy("estado", "categoria") \
    .mode("overwrite") \
    .parquet("/FileStore/tables/dados/vendas_por_estado_categoria")
```

Exemplo de estrutura:

- `vendas_por_estado_categoria/estado=MG/categoria=Ativo/`
- `vendas_por_estado_categoria/estado=MG/categoria=Inativo/`
- `vendas_por_estado_categoria/estado=SP/...`

Isso é útil quando diferentes times ou processos leem por estado e depois por categoria: cada um acessa só sua pasta, ganhando performance. A escrita pode demorar um pouco mais, mas a leitura filtrada fica mais rápida.

### 6.3. Ler uma partição ou todas

**Ler apenas uma partição** (ex.: dados do estado MG e categoria Ativo):

```python
df_filtrado = spark.read \
    .format("parquet") \
    .load("/FileStore/tables/dados/vendas_por_estado_categoria/estado=MG/categoria=Ativo/")
display(df_filtrado)
```

**Ler todas as partições** (todo o conjunto): use o caminho da pasta raiz do particionado. O Spark descobre e lê todas as subpastas:

```python
df_tudo = spark.read \
    .format("parquet") \
    .load("dbfs:/FileStore/tables/dados/vendas_por_categoria/")
display(df_tudo)
```

## 7. Resumo: quando usar cada formato

| Formato | Uso típico | Vantagens | Desvantagens |
|---------|------------|-----------|--------------|
| **CSV** | Troca de dados, exportações, planilhas, fontes externas | Simples, legível, universal | Sem tipos nativos, sem compactação por padrão, leitura mais pesada |
| **JSON** | APIs, dados semi-estruturados, integrações | Flexível, suporta aninhamento | Pode ser verboso e maior que Parquet |
| **Parquet** | Camada processada no Data Lake, tabelas analíticas | Compacto, rápido, particionável, colunar | Menos legível “a olho”, menos compatível com ferramentas que só leem CSV/JSON |

**Sugestão prática:** ingerir em CSV ou JSON quando for o que a fonte entrega; depois, no pipeline, **gravar em Parquet** (e, se fizer sentido, particionado) para as camadas de consumo e análise no Databricks.
