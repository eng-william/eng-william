## 1. Introdução: SQL no Databricks

No Databricks você pode usar **SQL** de duas formas principais:

- **Células SQL:** no notebook, selecione o idioma **SQL** na célula (ou use o *magic* `%sql`). O comando é executado diretamente no motor Spark SQL.
- **Python + Spark:** use `spark.sql("sua consulta")` para executar SQL e receber o resultado como **DataFrame**.

As tabelas criadas ficam no **metastore** (catálogo de metadados). No **metastore padrão (legacy)** do Databricks, bancos e tabelas são armazenados no cluster; ao desligar o cluster, os **metadados** (estrutura dos bancos e tabelas) podem ser perdidos, dependendo da configuração — os **arquivos no DBFS** permanecem. Com **Unity Catalog**, o catálogo é gerenciado centralmente e o uso de caminhos para criar tabelas segue regras específicas (ex.: caminhos com esquema de nuvem como `dbfs:/` ou Volumes).

Este material cobre o fluxo típico: criar banco, criar tabelas a partir de arquivos ou DataFrames, executar SQL e salvar resultados em diferentes formatos.

## 2. Referência rápida — comandos SQL essenciais

Use esta seção como **fonte de consulta** nos primeiros trabalhos. A sintaxe segue o padrão Spark SQL no Databricks.

### 2.1. Banco de dados (schema)

| Ação | Comando |
|------|---------|
| **Criar banco** | `CREATE DATABASE IF NOT EXISTS nome_do_banco;` |
| **Usar um banco** | `USE nome_do_banco;` |
| **Listar bancos** | `SHOW DATABASES;` |
| **Excluir banco** (deve estar vazio ou usar CASCADE) | `DROP DATABASE IF EXISTS nome_do_banco;` ou `DROP DATABASE IF EXISTS nome_do_banco CASCADE;` |
| **Ver banco atual** | `SELECT current_database();` |

### 2.2. Tabelas

| Ação | Comando |
|------|---------|
| **Criar tabela a partir de arquivo CSV** | `CREATE TABLE IF NOT EXISTS nome_tabela USING csv OPTIONS ('path' '/caminho/arquivo.csv', 'header' 'true', 'inferSchema' 'true');` |
| **Criar tabela vazia** (com colunas) | `CREATE TABLE IF NOT EXISTS nome_tabela (col1 STRING, col2 INT, col3 DATE);` |
| **Listar tabelas do banco** | `USE nome_do_banco; SHOW TABLES;` ou `SHOW TABLES IN nome_do_banco;` |
| **Descrever tabela** | `DESCRIBE TABLE nome_do_banco.nome_tabela;` ou `DESCRIBE TABLE nome_tabela;` (com `USE`) |
| **Renomear tabela** | `ALTER TABLE nome_do_banco.nome_antigo RENAME TO nome_novo;` |
| **Excluir tabela** | `DROP TABLE IF EXISTS nome_do_banco.nome_tabela;` ou `DROP TABLE IF EXISTS nome_tabela;` (com `USE`) |
| **Truncar tabela** (apagar dados, manter estrutura) | `TRUNCATE TABLE nome_do_banco.nome_tabela;` |

### 2.3. Consultas (DML)

| Ação | Exemplo |
|------|---------|
| **Selecionar** | `SELECT * FROM nome_do_banco.nome_tabela;` ou, após `USE nome_do_banco;`, `SELECT * FROM nome_tabela;` |
| **Contar linhas** | `SELECT COUNT(*) FROM nome_tabela;` |
| **Filtrar** | `SELECT * FROM nome_tabela WHERE coluna = 'valor';` |
| **Agrupar** | `SELECT coluna, COUNT(*) AS qtd FROM nome_tabela GROUP BY coluna;` |
| **Filtrar grupos** | `SELECT coluna, COUNT(*) AS qtd FROM nome_tabela GROUP BY coluna HAVING COUNT(*) > 10;` |
| **Ordenar** | `SELECT * FROM nome_tabela ORDER BY coluna DESC;` |
| **Limitar linhas** | `SELECT * FROM nome_tabela ORDER BY coluna DESC LIMIT 100;` |

### 2.4. Dicas rápidas

- Sempre que for criar ou acessar tabelas em um banco, use `USE nome_do_banco;` na mesma célula (ou antes) para não precisar qualificar o nome: `nome_do_banco.nome_tabela`.
- `IF NOT EXISTS` e `IF EXISTS` evitam erros ao criar ou dropar objetos que já existem ou não existem.
- No **Unity Catalog**, o caminho em `CREATE TABLE ... OPTIONS ('path' ...)` deve usar esquema de nuvem (ex.: `dbfs:/FileStore/...` ou caminho em Volume). No metastore legacy, `/FileStore/...` costuma funcionar.

## 3. Criar banco de dados

Crie o banco com SQL em uma célula **SQL** (`%sql`):

```sql
CREATE DATABASE IF NOT EXISTS teste;
```

Para usar esse banco nas próximas instruções da mesma célula (ou das seguintes, dependendo do contexto):

```sql
USE teste;
```

Em seguida, você pode criar tabelas nesse banco. Exemplo completo em uma única célula:

```sql
CREATE DATABASE IF NOT EXISTS teste;
USE teste;
-- suas CREATE TABLE e SELECT aqui
```

## 4. Criar tabela a partir de arquivo (CSV no DBFS)

Você registra um arquivo CSV que já está no DBFS (ou em um Volume) como tabela SQL. Assim, pode fazer `SELECT` e outras operações SQL sobre o arquivo.

### 4.1. Sintaxe básica (metastore legacy / DBFS)

Certifique-se de que o arquivo está no DBFS (ex.: `/FileStore/tables/Bikes/products.csv`). Em uma célula SQL:

```sql
USE teste;

CREATE TABLE IF NOT EXISTS produtos
USING csv
OPTIONS (
  'path' '/FileStore/tables/Bikes/products.csv',
  'header' 'true',
  'inferSchema' 'true'
);
```

- **path:** caminho do arquivo no DBFS.
- **header:** `'true'` indica que a primeira linha é cabeçalho.
- **inferSchema:** `'true'` infere tipos das colunas automaticamente.

Depois, consulte com:

```sql
SELECT * FROM produtos;
```

### 4.2. Várias tabelas de uma vez

Você pode criar várias tabelas na mesma célula:

```sql
USE teste;

CREATE TABLE IF NOT EXISTS brands
USING csv OPTIONS ('path' '/FileStore/tables/Bikes/brands.csv', 'header' 'true', 'inferSchema' 'true');

CREATE TABLE IF NOT EXISTS categories
USING csv OPTIONS ('path' '/FileStore/tables/Bikes/categories.csv', 'header' 'true', 'inferSchema' 'true');

CREATE TABLE IF NOT EXISTS clientes
USING csv OPTIONS ('path' '/FileStore/tables/Bikes/customers.csv', 'header' 'true', 'inferSchema' 'true');

-- repetir para orders, order_items, products, etc.
```

### 4.3. Unity Catalog

No **Unity Catalog**, criar tabela apontando direto para um caminho exige que o caminho tenha **esquema de nuvem** (ex.: `dbfs:/...`) e que o local esteja com permissões e credenciais configuradas. Se der erro do tipo *"Missing cloud file system scheme"*, use o caminho completo com `dbfs:` (ex.: `'path' 'dbfs:/FileStore/tables/Bikes/products.csv'`) ou prefira usar **Volumes** e caminhos em Volumes, conforme a documentação do seu workspace.

## 5. Criar tabela a partir de um DataFrame (Spark/Python)

Em vez de criar a tabela via SQL a partir de um arquivo, você pode criar a tabela a partir de um **DataFrame** já carregado em Python.

### 5.1. Método simples: vista temporária + SQL

1. Carregue o CSV em um DataFrame (célula Python):

```python
df = spark.read.csv("/FileStore/tables/Bikes/customers.csv", header=True, inferSchema=True)
```

2. Registre o DataFrame como **tabela temporária** (visível só na sessão atual):

```python
df.createOrReplaceTempView("clientes")
```

3. Use SQL normalmente (em célula SQL ou em `spark.sql()`):

```sql
SELECT * FROM clientes;
```

A tabela `clientes` deixa de existir quando a sessão terminar.

### 5.2. Salvar como tabela persistente no metastore

Para gravar o conteúdo do DataFrame como **tabela persistente** no catálogo (e opcionalmente em um caminho):

```python
df.write.saveAsTable("teste.clientes")
```

Ou com modo de escrita e formato:

```python
df.write.mode("overwrite").saveAsTable("teste.clientes")
```

Assim a tabela `teste.clientes` pode ser usada em qualquer notebook ou job que acesse o mesmo metastore.

## 6. Executar SQL e obter resultado em DataFrame

Use `spark.sql()` em uma célula **Python** para executar uma consulta e receber o resultado como DataFrame. Isso é útil para combinar lógica SQL com processamento em PySpark.

### 6.1. Exemplo básico

Primeiro, a tabela precisa existir (criada por SQL ou por `createOrReplaceTempView` / `saveAsTable`). Depois:

```python
df_resultado = spark.sql("""
    SELECT customer_id, first_name, phone, email
    FROM clientes
    WHERE first_name LIKE '%sha%'
""")

df_resultado.show()
# ou
display(df_resultado)
```

### 6.2. Usando aspas triplas

Para consultas longas, use aspas triplas (`'''` ou `"""`) para quebrar em várias linhas:

```python
DfSQL = spark.sql('''
    SELECT
        customer_id AS Id,
        first_name AS Nome,
        phone AS Telefone,
        email AS Email
    FROM Clientes
    WHERE first_name LIKE "%sha%"
''')

display(DfSQL)
```

Esse DataFrame pode ser usado em seguida para salvar em Parquet, CSV, JSON ou outra tabela (veja seções abaixo).

## 7. Consultas SQL em arquivo externo

Quando a consulta fica muito grande, uma boa prática é manter o SQL em um **arquivo** no repositório ou no DBFS e carregar o conteúdo em uma variável antes de executar.

### 7.1. Arquivo no projeto (workspace)

Exemplo: você tem um arquivo `queries/consulta_clientes.sql` no seu projeto. No notebook (Python), leia o arquivo e execute:

```python
# Caminho do arquivo no workspace (ajuste conforme sua estrutura)
caminho_sql = "/Workspace/Users/seu_email@empresa.com/meu_projeto/queries/consulta_clientes.sql"

with open(caminho_sql, "r", encoding="utf-8") as f:
    query = f.read()

df = spark.sql(query)
display(df)
```

Se o arquivo estiver no DBFS:

```python
# Exemplo: arquivo no DBFS
caminho_sql = "/dbfs/FileStore/tables/queries/consulta_clientes.sql"
with open(caminho_sql, "r", encoding="utf-8") as f:
    query = f.read()
df = spark.sql(query)
```

Assim você mantém consultas complexas versionadas e reutilizáveis.

## 8. Salvar DataFrame em CSV, JSON e Parquet

Depois de ter um DataFrame (por exemplo, resultado de `spark.sql()` ou de `spark.read.csv`), você pode gravá-lo em diferentes formatos no DBFS.

### 8.1. Modos de escrita

| Modo | Descrição |
|------|------------|
| `overwrite` | Substitui o conteúdo existente no caminho. |
| `append` | Adiciona dados ao que já existe (cuidado com esquema). |
| `ignore` | Só grava se o caminho não existir. |

### 8.2. Parquet

Parquet é formato colunar, compactado e muito usado em Data Lakes. O Spark grava uma **pasta** com arquivos `.parquet` (o caminho é o nome da “tabela” em disco):

```python
# Criar pasta de saída se quiser (opcional)
dbutils.fs.mkdirs('/FileStore/tables/DiferentesSaidas')

DfSQL.write.mode("overwrite").parquet("/FileStore/tables/DiferentesSaidas/ContatoSha.parquet")
```

Verificar o que foi gravado:

```python
display(dbutils.fs.ls("/FileStore/tables/DiferentesSaidas/ContatoSha.parquet"))
```

### 8.3. CSV

O Spark grava CSV como **pasta** com arquivos part-*.csv. Use `option("header", "true")` para incluir cabeçalho:

```python
DfSQL.write \
    .option("header", "true") \
    .option("delimiter", ",") \
    .mode("overwrite") \
    .csv("/FileStore/tables/DiferentesSaidas/ContatoSha.csv")
```

Para ler de volta (a pasta, não um arquivo único):

```python
df_csv = spark.read.csv("/FileStore/tables/DiferentesSaidas/ContatoSha.csv", header=True, inferSchema=True)
display(df_csv)
```

### 8.4. JSON

Cada linha vira um objeto JSON; a saída também é uma **pasta** com arquivos:

```python
DfSQL.write.mode("overwrite").json("/FileStore/tables/DiferentesSaidas/ContatoSha.json")
```

Ler de volta:

```python
df_json = spark.read.json("/FileStore/tables/DiferentesSaidas/ContatoSha.json")
display(df_json)
```

## 9. Particionamento de dados (Parquet)

Particionar ajuda a acelerar consultas que filtram por uma ou mais colunas (ex.: estado, data). Os dados são gravados em subpastas por valor da coluna de partição.

### 9.1. Gravar Parquet particionado

Use `.partitionBy("coluna")` antes de `.parquet()`:

```python
novodf = spark.sql("SELECT * FROM clientes")

novodf.write \
    .partitionBy("state") \
    .mode("overwrite") \
    .parquet("/FileStore/tables/DiferentesSaidas/Contato_Particionado.parquet")
```

Isso gera uma estrutura de pastas como:

- `Contato_Particionado.parquet/state=CA/`
- `Contato_Particionado.parquet/state=NY/`
- `Contato_Particionado.parquet/state=TX/`
- ...

### 9.2. Múltiplas colunas de partição

```python
novodf.write \
    .partitionBy("state", "city") \
    .mode("overwrite") \
    .parquet("/FileStore/tables/DiferentesSaidas/Clientes_Particionado.parquet")
```

### 9.3. Ler dados particionados

Ler **toda** a pasta (o Spark descobre as partições):

```python
df = spark.read.parquet("/FileStore/tables/DiferentesSaidas/Contato_Particionado.parquet")
display(df)
```

Ler **apenas** uma partição (ex.: `state=CA`):

```python
df_ca = spark.read.parquet("/FileStore/tables/DiferentesSaidas/Contato_Particionado.parquet/state=CA/")
display(df_ca)
```

## 10. CSV compactado (GZIP)

Salvar CSV com compactação **gzip** reduz o tamanho do arquivo e é útil para armazenamento e transferência.

### 10.1. Gravar CSV em GZIP

```python
df.write \
    .format("csv") \
    .option("header", "true") \
    .option("compression", "gzip") \
    .option("sep", ",") \
    .mode("overwrite") \
    .save("/FileStore/tables/DiferentesSaidas/arquivo.csv")
```

A pasta resultante terá arquivos com extensão `.gz`. Para **ler** o CSV compactado:

```python
df_lido = spark.read \
    .option("compression", "gzip") \
    .option("header", "true") \
    .option("inferSchema", "true") \
    .option("sep", ",") \
    .csv("/FileStore/tables/DiferentesSaidas/arquivo.csv")
display(df_lido)
```

## 11. Como visualizar os logs das ações

Para entender o que o Spark está executando e onde pode estar lento ou falhando, use os recursos de **log** e **UI** do Databricks.

### 11.1. Spark UI (interface do Spark)

- Com o cluster ligado, no notebook: clique no **ícone de cluster** (canto superior direito) ou no link **Spark UI**.
- Na Spark UI você vê:
  - **Jobs:** quais jobs foram disparados (ex.: por um `collect`, `show`, `write`).
  - **Stages e Tasks:** estágios da execução e tarefas.
  - **Event Timeline:** linha do tempo da execução.
  - **Storage:** cache e dados em memória.

Isso ajuda a ver se uma ação (por exemplo um `write` ou um `display`) gerou um job e como ele se comportou.

### 11.2. Logs do driver (Driver logs)

- No menu do cluster: **Driver logs** (ou **Logs**).
- Mostram saída de `print()`, mensagens do driver e stack traces de erros. Útil para depurar código Python e exceções.

### 11.3. Saída do notebook

- A saída de cada célula (incluindo erros e stack traces) fica logo abaixo da célula. Em jobs agendados, confira a **run** do job e a saída de cada célula na execução.

### 11.4. Histórico de SQL (opcional)

- Em alguns workspaces é possível acessar o **SQL Query History** ou o histórico de comandos do Spark para revisar as queries executadas.

Com isso você consegue acompanhar as “ações” (jobs, estágios e logs) das suas escritas e leituras.

## 12. Observações importantes

- **Metastore e cluster:** No metastore padrão (legacy), metadados de bancos e tabelas podem estar associados ao cluster. Verifique a política do workspace; em alguns casos, ao desligar o cluster, você perde apenas as tabelas temporárias, não as persistentes.
- **DBFS:** Arquivos gravados no DBFS (ex.: `/FileStore/tables/...`) **persistem** mesmo após desligar o cluster.
- **Caminhos:** Ao criar tabela com `OPTIONS ('path' ...)`, no Unity Catalog use caminho com esquema (ex.: `dbfs:/...`). Em Volumes, use o caminho do Volume conforme a documentação.
- **CSV/JSON no Spark:** `write.csv` e `write.json` geram **pastas** com vários arquivos (partes). Para um único arquivo, seria necessário coalesce (ex.: `coalesce(1)`), o que pode ser custoso em grandes volumes; em geral, pastas com múltiplas partes são o esperado em ambiente distribuído.
