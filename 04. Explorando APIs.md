## 📌 O que é uma API?

**API** (*Application Programming Interface*) é um conjunto de regras que permite a comunicação entre diferentes sistemas.

> Funciona como um **pedido em um restaurante** 🍽️: você faz o pedido (request 🙋‍♂️) ao **garçom** (API 🤵🏻), que o leva até a **cozinha** (aplicação 👨‍🍳) para preparar a **comida** (process 🍳).  
> Em seguida, o **garçom** (API 🤵🏻) retorna trazendo a **refeição** (response 🥗) que você solicitou.

---

## ⚙️ Como funciona uma solicitação de API

1️⃣ **Request** 🙋‍♂️ → Cliente faz um pedido à API 🤵🏻  
2️⃣ **Process** 🤵🏻 → API entrega o pedido para a aplicação 👨‍🍳  
3️⃣ **Response** 🤵🏻 → API retorna a resposta ao cliente 🥗🙋‍♂️

> Toda API tem uma **documentação**, que funciona como um cardápio. Nela estão todos os serviços disponíveis e como fazer as solicitações.

---

## 🚀 Por que usar APIs?

- **Integração** → Conecta diferentes plataformas e serviços.  
- **Automação** → Evita tarefas manuais, como atualizar planilhas.  

> Sem APIs, nenhuma automação real seria possível.

---

## 📖 Termos Chave API

- ✅ **API Endpoint** → O endereço web (URL) onde as requisições são enviadas.  
- ✅ **API Call** → A requisição feita para uma API.  
- ✅ **HTTP Request** → O método utilizado para fazer uma requisição para a API.  

---

## 🛠 Estrutura de uma requisição de API

- **URL** → Endereço do recurso ou serviço.  
- **Método (Method)** → Tipo de ação (GET, POST, PUT, DELETE).  
- **Cabeçalhos (Headers)** → Informações adicionais, como chave de API.  
- **Corpo (Body)** → Dados enviados (em JSON, XML, etc.), usados em POST/PUT.  

---

## 📚 Métodos HTTP mais usados

- **GET** → Obter dados.  
- **POST** → Adicionar novos dados.  
- **PUT/PATCH** → Atualizar dados existentes.  
- **DELETE** → Remover dados.  

---

## 📥 Resposta de uma API

Uma resposta típica contém:  

- **Código de Status (Status Code)** → 200 (OK), 401 (Não autorizado), 404 (Não encontrado).  
- **Cabeçalhos (Headers)** → Informações extras, como tipo de conteúdo.  
- **Corpo (Body)** → Os dados retornados.

---

## 🌐 HTTP Status Codes – Guia Completo

| Código | Significado                  | Descrição                                                                 |
|--------|-----------------------------|---------------------------------------------------------------------------|
| ℹ️ 100 | Continue                    | O cliente deve continuar com a requisição.                                |
| ℹ️ 101 | Switching Protocols         | O servidor vai mudar de protocolo conforme solicitado pelo cliente.       |
| ℹ️ 102 | Processing                  | Servidor recebeu a requisição e está processando.                          |
| ✅ 200 | OK                          | Requisição bem-sucedida.                                                  |
| ✅ 201 | Created                     | Recurso criado com sucesso.                                               |
| ✅ 202 | Accepted                    | Requisição aceita, mas ainda em processamento.                            |
| ✅ 203 | Non-Authoritative Information | Informação retornada não é exatamente do servidor original.             |
| ✅ 204 | No Content                  | Requisição bem-sucedida, sem conteúdo a retornar.                         |
| ✅ 205 | Reset Content               | Solicita que o cliente resete o documento de visualização.               |
| ✅ 206 | Partial Content             | Conteúdo parcial retornado devido a um range header.                      |
| ⚠️ 300 | Multiple Choices            | Existem múltiplas opções de resposta.                                     |
| ⚠️ 301 | Moved Permanently           | Recurso movido permanentemente para outra URL.                            |
| ⚠️ 302 | Found                       | Recurso temporariamente em outra URL.                                     |
| ⚠️ 303 | See Other                   | Cliente deve usar GET para acessar outro recurso.                         |
| ⚠️ 304 | Not Modified                | Recurso não modificado desde a última requisição.                          |
| ⚠️ 307 | Temporary Redirect          | Redirecionamento temporário mantendo o método HTTP.                        |
| ⚠️ 308 | Permanent Redirect          | Redirecionamento permanente mantendo o método HTTP.                        |
| ❌ 400 | Bad Request                 | Requisição inválida ou malformada.                                        |
| ❌ 401 | Unauthorized                | Falta autenticação válida.                                                |
| ❌ 403 | Forbidden                   | Servidor entendeu a requisição, mas se recusa a autorizar.                |
| ❌ 404 | Not Found                   | Recurso não encontrado.                                                   |
| ❌ 405 | Method Not Allowed          | Método HTTP não permitido para o recurso.                                 |
| ❌ 406 | Not Acceptable              | Recurso não aceita o tipo de conteúdo solicitado.                          |
| ❌ 407 | Proxy Authentication Required | Autenticação com proxy necessária.                                      |
| ❌ 408 | Request Timeout             | Requisição demorou demais para ser completada.                             |
| ❌ 409 | Conflict                    | Conflito ao processar a requisição (ex: duplicidade de recurso).           |
| ❌ 410 | Gone                        | Recurso não está mais disponível permanentemente.                          |
| ❌ 411 | Length Required             | Cabeçalho Content-Length necessário.                                       |
| ❌ 412 | Precondition Failed         | Pré-condição na requisição falhou.                                         |
| ❌ 413 | Payload Too Large           | Corpo da requisição maior do que o servidor aceita.                        |
| ❌ 414 | URI Too Long                | URI solicitada muito longa.                                                |
| ❌ 415 | Unsupported Media Type      | Tipo de mídia não suportado pelo servidor.                                 |
| ❌ 416 | Range Not Satisfiable       | Intervalo solicitado não pode ser atendido.                                |
| ❌ 417 | Expectation Failed          | Servidor não consegue atender à expectativa do cabeçalho Expect.           |
| ❌ 426 | Upgrade Required            | Cliente deve atualizar o protocolo.                                        |
| 🖥️ 500 | Internal Server Error       | Erro interno no servidor.                                                 |
| 🖥️ 501 | Not Implemented             | Servidor não implementa a funcionalidade solicitada.                        |
| 🖥️ 502 | Bad Gateway                 | Servidor recebeu resposta inválida de outro servidor.                     |
| 🖥️ 503 | Service Unavailable         | Servidor temporariamente indisponível.                                     |
| 🖥️ 504 | Gateway Timeout             | Servidor não recebeu resposta a tempo de outro servidor.                  |
| 🖥️ 505 | HTTP Version Not Supported  | Versão HTTP não suportada pelo servidor.                                   |

### 🔹 Resumo dos Códigos de Status

- ℹ️ **1xx (Information)** - Requisição recebida, servidor está processando.  
- ✅ **2xx (Success)** – Requisição bem-sucedida; tudo funcionou como esperado.  
- ⚠️ **3xx (Redirection)** – Recurso foi movido ou há múltiplas opções; atenção ao redirecionamento.  
- ❌ **4xx (Client Error)** – Erro na requisição do cliente; precisa ser corrigido.  
- 🖥️ **5xx (Server Error)** – Erro no servidor; geralmente precisa tentar novamente mais tarde.

## 🔐 Autenticação

A maioria das APIs exige autenticação via **chave** ou **token**.  
No n8n, isso é feito adicionando **headers** de autorização.  

---

## 🛑 Erros comuns e como resolver

- **401 Unauthorized** → Verifique a chave ou token.  
- **404 Not Found** → Confira a URL.  
- **400 Bad Request** → Corpo da requisição inválido (geralmente JSON mal formatado).  
- **Incorrect Method** → Ex.: tentar usar GET quando a API espera POST.  

💡 **Dica:** Sempre verifique o *Execution Log* no n8n para identificar o problema.

---

## ✅ Exemplo prático no n8n (HTTP Request Node)

1. Adicione o nó **HTTP Request**.  
2. Defina a **URL** da API.  
3. Escolha o **método** (GET, POST...).  
4. Configure **headers** (incluindo a chave de API).  
5. *(Opcional)* Adicione um **corpo** para requisições POST.  
6. Execute o nó e processe a resposta.  

---

## 📌 Conclusão

- As APIs são a **espinha dorsal** das automações no n8n e sem elas nenhuma automação é possível.  
- Saber criar requisições corretamente (**URL**, **Method**, **Headers** e **Body**) é essencial.  
- O nó **HTTP Request** é extremamente versátil e permite integrar praticamente qualquer serviço.  
- Entender e interpretar **códigos de status** facilita a depuração de problemas.  

✨ **Resumo:** Dominar o uso de APIs no n8n significa poder integrar praticamente qualquer ferramenta ou serviço, tornando suas automações mais **poderosas**, **flexíveis** e **inteligentes**.
